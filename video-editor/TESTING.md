## 端末・ブラウザによる違い (設計上の想定)

| 項目 | Chrome (Android/PC) | Safari (iPhone/iPad) |
| --- | --- | --- |
| H.264 書き出し | WebCodecs (ハードウェア) | WebCodecs (Safari 16.4 以降)。それ以前は実時間録画 (MediaRecorder, MP4) |
| AAC 符号化 | 端末により WebCodecs / WASM | WebCodecs 非対応版では WASM エンコーダ (自動切替) |
| 書き出しファイルの一時保存 | OPFS (ストリーム書き込み) | OPFS の書き込み API 非対応版ではメモリ上 (長尺ではメモリ不足の恐れ) |
| 写真への保存 | ダウンロード / 共有 | 共有シート →「ビデオを保存」 |
| 音声プレビュー | 通常 | **消音スイッチがオンだと Web Audio の音が出ない** (iOS の仕様) |
| 同時に扱える動画デコーダ | 多い | 少ないため同時再生する `<video>` を 4 個に制限 |
| 4K | エンコーダが対応を返せば選択可 | メモリ 4GB 未満相当・テクスチャ上限 8192 未満では無効化 |

## 未完成機能・既知の不具合・制限事項

1. **実機テスト未実施**: iPhone (Safari) / Android (Chrome) の実機での操作性・性能・書き出しは未検証です。
2. **プレビューの逆再生・4 倍速超**: プレビューはシーク方式のためカクつきます (書き出しは正確)。
3. **速度変更で音程が変わる** (タイムストレッチ未実装)。
4. **モーションブラー / 残像は変形 (位置・回転・拡大) の動きから計算**: 動画内の被写体の動きにはかかりません。
5. **プロキシ動画 (低解像度変換) は未実装**: プレビューは表示解像度で描画しますが、動画デコード自体は元素材です。4K 素材は端末によって重くなります。
6. **長尺の目安**: 15 分・1080p は自動テスト (PC の Chromium) で検証済み。iPhone 実機では未検証です。端末の空き容量は書き出しサイズ (1080p30 で約 90MB/分、ビットレート自動時) の 1.1 倍以上が必要です。2.5 分以下の音声素材は従来どおり全体をデコードします。
7. **サーバーレンダリングは未実装**: 端末で処理できない場合の構成として「同じ Compositor を Headless Chromium + GPU で動かし、素材をアップロードして書き出す」方式を検討しましたが、有料サービスの利用判断が必要なため実装していません。
8. **書き出し中にアプリを切り替えると停止**する場合があります (iOS のバックグラウンド制限)。Wake Lock 対応端末では画面消灯を防止します。
9. **WebCodecs 非対応端末の書き出し** は実時間録画のためフレーム落ちが起こり得ます。MP4 録画非対応のブラウザでは WebM になります。
10. **マスクは矩形・楕円のみ** (ペンツールの自由曲線マスクは未実装)。
11. **パス追従アニメーション** (曲線に沿った移動・空間ベジェ) は未実装。位置キーフレーム間は直線移動です。
12. **縦書き**: 句読点・括弧・長音の置き換え/回転には対応していますが、英数字の縦中横には未対応です。
13. **エフェクトの演算精度は 8bit** (RGBA8): 強いグローや LUT でバンディングが出る場合があります。
14. **Web フォント** は初回にネットワークが必要です (Service Worker でキャッシュ後はオフライン可)。
15. **プロジェクトファイル (.json) の書き出しには素材が含まれません**。
16. **Undo 履歴は再読み込みで消えます** (編集内容自体は保存されます)。
17. **トランジション** は同じトラックで隣接している (半フレーム以内) クリップ間のみ。
18. **HEIC 画像** は Safari でのみ読み込めます。
19. ソフトウェア GL (GPU なし) の自動テスト環境での速度: 1080p60 の重い構成 (モーションブラー + グロー + パーティクル) で書き出し約 1fps、720p の単純な構成で約 24fps、プレビュー 8〜11fps。GPU のある実機ではより高速になる想定ですが**未計測**です。
